# Contributing to the Equilens Website

Thanks for helping keep the FL‑BSA site tidy and deterministic. This project is a
static HTML/CSS codebase deployed from `main` via GitHub Pages, so every change
should be reproducible and auditable.

## Project layout

```
assets/               Runtime CSS, JS (served to the browser)
brand/                Source design tokens, press kit, wordmarks
config/web/           JSON single source of truth (SSOT) for nav and footer
templates/            HTML partials (footer partial injected by the sync script)
output/ops/           Evidence artefacts generated by CI (kept intentionally)
scripts/              Tooling (SEO, OG rendering, evidence, content sync, etc.)
```

### CSS & JS

- `assets/eql/base.css` – all site styles (design tokens aliased from
  `brand/tokens/tokens.css` via `@import`)
- `assets/eql/nav.js` – renders the navbar at runtime from `config/web/nav.json`
  into `#nav-placeholder`, plus smooth scroll, mobile menu, and TOC scroll-spy
- `assets/eql/contact.js` – contact form mailto builder (no server submission)

No bundler is involved; keep the styles lean and deterministic.

## Updating navigation & footer

**Navigation** is rendered at runtime by `assets/eql/nav.js` from
`config/web/nav.json` — edit the JSON and the change applies everywhere on the
next page load. No sync script is involved.

**The footer** is baked into each page and synchronised from
`config/web/footer.json` (links, copyright note, product-boundary disclaimer)
plus the partial `templates/footer.html`. **Never edit page footers by hand**;
changes will be overwritten.

1. Update `config/web/footer.json` and/or `templates/footer.html`.
2. Run the sync script:

   ```bash
   python3 scripts/content/sync_footer_ssot.py
   ```

3. Review the generated diffs (`git status`, `git diff`) and run the Playwright
   suite — tests assert the footer's labeled heading and product-boundary
   disclaimer on every page.

Legacy, currently unused: `templates/header.html` +
`scripts/content/sync_nav_ssot.py` (superseded by the runtime nav renderer)
and `templates/flbsa_subnav.html` (no page includes a product sub-nav). Kept
for reference only; do not run the nav sync against current pages.

## Evidence & tooling

- Generate screenshot/evidence bundles locally with
  `scripts/evidence/screenshots.sh`.
- The deployment workflow (`.github/workflows/pages.yml`) runs the same evidence
  command and stores artefacts under `output/ops/SITE-DEPLOY-<timestamp>/`.
- Keep `output/ops/` committed when new evidence is generated – it is part of
  the compliance trail.

## Working locally

```bash
python3 -m http.server  # serves the repo at http://localhost:8000
```

Use the provided scripts wherever possible (SEO toggles, OG renderer, icon
generator, legal verifiers) so the CI and local environments stay in sync.

## Git hygiene

- Commit small, reviewable changes.
- Attach the evidence bundle (when applicable) in the same commit.
- Never rewrite history on `main`; deployments track that branch directly.

If in doubt, ask before removing files – several “unused” assets are referenced
by the evidence or deploy scripts.
